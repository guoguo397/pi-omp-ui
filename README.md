# pi-omp-ui

自己用 AI 改的 Pi UI 扩展（自用，请温柔喷）。仿 OMP 输入框和 Claude Code 状态栏，提供执行 / 计划两种交互模式；执行模式保留 Pi 原生编辑与工具调用行为，无需安装 `pi-cc-extensions`。

## 功能

- **输入框**：圆角左边框、开放右侧、紧凑留白，保留原生编辑行为；拖入或粘贴本地图片路径时显示 `[Image #N]` 标签，发送仍使用原路径，支持整体删除和撤销。
- **工具 UI**：紧凑卡片、连续调用分组、运行状态和耗时；可展开完整输入、输出及图片。Codemode 显示子调用进度，Edit 支持宽屏并排 diff、窄屏统一 diff。
- **消息背景**：已发送用户消息的背景向终端底色混合 20%，减弱色块对比；文字、输入框及其他消息背景不变，跟随主题和终端底色更新。随扩展默认启用，无独立开关。
- **完成统计与标题**：整轮执行结束后，在输入框顶边居中显示“本轮耗时 · 会话累计耗时”；顶边右侧显示已有会话标题，不增加行数。
- **状态栏**：展示模型、项目、Git、耗时、Context 进度条、上下文文件 / MCP 数、思考等级、用量、本轮平均输出速率和插件状态；有本轮工具调用记录时追加次数汇总。
- **轻量任务子 agent**：主 agent 可将明确、低风险且仅需修改一个文件的任务委派给 `flash`，固定使用 `deepseek/deepseek-flash`、思考强度 `low`；主 agent 验收并运行测试。
- **执行 / 计划模式**：`Shift+Tab` 在 `accept edits on` 与 `plan mode` 之间切换；计划模式限制工具调用，只分析并输出方案，不自动执行。

界面和模式功能仅在交互式终端启用，不改变 RPC、JSON 或打印模式。执行模式不额外限制工具；计划模式在工具执行前进行拦截，不替换工具实现。包版本为 **2.0.0**，已在 **Pi 1.3.0** 验证，其他 Pi 版本尚未验证。本文描述当前源码行为，尚未发布的变更见 [更新日志](./CHANGELOG.md)。

## 环境要求

- 已安装 Pi；本项目不是独立应用，也不是 OMP 官方插件。
- Node.js **22.19+**。
- 使用 Pi 的交互式终端界面，支持 Fullscreen 和 Regular 模式。
- 自动会话命名和 `flash` 需要 Pi 中可用的 `deepseek/deepseek-flash` 模型与鉴权；不依赖 `pi-subagents`，缺少模型或鉴权不影响其他 UI 功能。

## 安装与更新

```bash
pi install git:github.com/guoguo397/pi-omp-ui
```

更新：

```bash
pi update git:github.com/guoguo397/pi-omp-ui
```

安装或更新后重启 Pi，或执行 `/reload`。

如需固定版本，在来源后加 `@标签`，例如：

```bash
pi install git:github.com/guoguo397/pi-omp-ui@v2.0.0
```

固定标签不会跟随主分支更新，功能以对应版本的 README 为准；更新和卸载时使用安装时的完整来源。

> 如果手动安装过 `omp-editor.js` 或 `done.js`，请先将旧脚本移出 `~/.pi/agent/extensions/`，避免重复加载。备份也不要留在自动加载目录中。

## 使用

安装后，圆角输入框、紧凑工具 UI、完成耗时统计、自定义状态栏和自动会话命名始终启用，无需配置。消息背景样式也随扩展自动启用，不提供单独的功能开关命令。

### 执行与计划模式

仅提供两种模式，不包含自动模式或额外权限档位：

| 模式 | 状态栏显示 | 行为 |
| --- | --- | --- |
| 执行（默认） | `⏵⏵ accept edits on` | 保留正常工具调用，可编辑文件和执行命令；仍受 Pi 及其他扩展的限制 |
| 计划 | `⏸ plan mode` | 仅允许 `read`、`grep`、`find`、`ls`，用于分析代码、澄清需求和输出步骤 |

- **切换**：按 `Shift+Tab`，或使用 `/omp-mode execute`、`/omp-mode plan`；`/omp-mode status`（或不带参数）查看当前模式。
- **只在空闲时切换**：本轮运行、重试、压缩或排队任务尚未结束时拒绝切换；请先等待结束或按 `Escape` 中止。
- **计划模式不是仅改标签**：在模型提示中加入只读规划要求，并拦截编辑、写入、Bash / PowerShell、Codemode、MCP 和其他非白名单工具，包括通过 Pi 分发的嵌套调用；手动 `!` / `!!` Shell 命令也会被拦截。不会按名称猜测 MCP 工具是否只读，也不会自动开启原本禁用的工具。
- **计划完成后保持计划模式**：确认方案后，先切换到执行模式，再发送“按方案执行”等指令；切换本身不会自动提交消息或启动执行。
- **按会话分支保存**：重载、恢复会话和树导航会恢复当前分支最后保存的模式；新会话默认执行。输入框或状态栏被其他扩展替换时，计划限制仍然生效，原生状态栏仍可显示模式状态。
- **快捷键变化**：本扩展接管 `Shift+Tab`，不再用它切换思考等级；扩展弹窗及括号粘贴期间不接管该键。如需保留思考等级快捷键，可在 `~/.pi/agent/keybindings.json` 中为 `app.thinking.cycle` 设置其他按键。

> 计划模式是工具调用层的工作流限制，不是操作系统沙箱。它不能约束受信任扩展自行执行的代码，也不能保证其他扩展重写的同名只读工具没有副作用。

### 轻量任务子 agent：flash

- 仅在交互式执行模式启用。主 agent 按风险、影响范围和不确定性判断任务，确认需求明确、风险低且**只需修改一个已知文件**后，通过 `flash` 工具委派；多文件任务（包括需要同时更新测试或文档）不委派，也不拆分绕过。此判定依赖主模型遵循指导，不是确定性的自动分类器。
- 固定使用 `deepseek/deepseek-flash`、思考强度 `low`，不切换主对话模型。每次使用独立的进程内 `Agent`，继承当前有效系统提示和项目指令；任务上下文、范围及验收条件由主 agent 明确传入，不自动复制全部会话历史。与零工具、`high` 的标题子 agent `titler` 相互独立。
- 只下放当前可调用的 `read` / `grep` / `find` / `ls` / `edit` / `write`，不重新启用禁用工具。可读多个文件，但写入前校验真实路径，`edit` / `write` 只能操作指定文件；不下放 Shell、Codemode、MCP 或递归委派。所有工具通过 Pi 的 `ctx.executeTool()` 分发，保留参数、权限和事件检查；计划模式仍禁止调用 `flash`。
- 主 agent 核对结果并运行必要验证，`flash` 不运行测试。超过范围或需要澄清时应交回主 agent；模型不可用、鉴权失败或工具失败会明确报错，不静默换模型。限制为每次最多 8 轮模型请求、24 次工具调用、120 秒，同一会话仅运行一个 worker。
- Escape 中止、会话切换、重载和树导航会取消执行。取消后不再启动操作，并等待已开始的文件操作结束；已发生的修改不会自动回滚或重跑，主 agent 必须先核对现场。单文件限制是工具边界而非操作系统沙箱，不能约束受信任扩展自行执行代码或重写工具的副作用。
- 已启动调用通过工具结果记录，在资源行显示 `Agents flash` / `flash ×2`，可随会话记录恢复；启动前被拦截或模型缺失不计数。原生嵌套记录中的成功 `SKILL.md` 读取计入 Skills（嵌套记录被原生上限裁剪时可能不完整）。子模型已取得的用量计入会话 token / 费用，不混入主模型输出速率；忽略取消、始终不返回的供应商请求无法补记迟到用量。

### 工具展开

- **Fullscreen**：点击工具卡或分组标题展开 / 折叠。
- **Regular**：使用 Pi 原生工具展开快捷键，默认 **Ctrl+O**；Fullscreen 也支持。
- 工具组和 Codemode 折叠时最多显示最近 8 项；Edit 默认预览 20 行，展开查看完整内容。
- 工具摘要将用户主目录（如 `C:/Users/hy/`）缩写为 `~/`，其他目录路径保留；Read 摘要不显示 `offset` / `limit`。仅精简展示，实际参数及展开后的完整输入不变。
- Bash / PowerShell 标题只保留程序与最多两个子命令式裸词，不展开选项、正文或 token 参数；摘要最多 80 个显示列，并按窗口剩余宽度加 `…` 截断。复合命令保留省略提示，多行脚本显示 `Multiline script`；单卡、分组和 Codemode 子调用保持一致。这里只做展示启发式，不是完整 Shell 解析或安全脱敏；完整命令仍在展开后的 Input 中查看。
- 未知工具保留原渲染器。检测到 `pi-cc-extensions` 接管工具渲染时自动让位。

#### 耗时与会话标题

- 顶边耗时在重试、压缩及排队执行全部结束后更新；新一轮开始时清除。
- 顶边右半段显示会话名，每次重绘读取最新值。长标题按列宽截断，空间不足或显示上方滚动提示时隐藏，优先保留耗时与原生运行提示。输入框被其他扩展替换时，完成耗时统计回退到独立通知。
- 未命名会话在首轮正常交互结束后，自动调用内置标题子 agent `titler`，根据本分支的用户输入和 AI 回复概括简短标题，不再直接截取输入。固定使用 `deepseek/deepseek-flash`，默认思考强度为 `high`，不跟随主对话模型。建议中文 8–18 字或英文 3–8 个词，最长 40 字符；生成后不再自动改动，已有标题（包括旧版生成的标题）和手动命名均不覆盖。仍可通过 `/name 标题` 或扩展 `pi.setSessionName("标题")` 修改。
- 子 agent 由 Pi 的 `Agent` SDK 在进程内独立创建，不依赖 `pi-subagents`，不启动 Shell 子进程，不加载扩展、skills、全局或项目指令，不读写会话文件。它只复用 Pi 的模型注册表与鉴权，每次使用全新上下文和零工具进行一次后台模型请求；额外用量不计入主对话的 token / 费用统计。不阻塞正常回复，也不向主对话插入消息。只发送有长度限制的对话正文，不含工具结果、图片或推理内容。
- 缺少模型、鉴权失败或 120 秒超时后保持未命名，每个会话最多警告一次并说明原因，后续有效交互结束时可重试；不回退到主模型或输入原文。空输入、斜杠命令、取消的执行及非 TUI 模式不触发命名；切换会话、重载、树导航或手动改名时取消旧请求，并忽略迟到结果。
- 顶边“会话累计”和状态栏耗时均从本次会话启动、切换会话或最近一次 `/reload` 重新计时，不是历史会话总耗时；顶边在本轮结束时更新，状态栏随界面重绘更新。

#### 上下文与用量

- 状态栏读取真实会话数据。Context 未知时显示 `?%`；MCP 数为提供可访问工具的命名空间数，不是配置总数。
- 输入 / 输出用量为会话累计值，输入包含缓存读写，费用为零时隐藏。`Working` 只在输入框显示，底部不重复。
- 资源行在 MCP 数后显示会话累计的子 agent 与技能调用（`Agents titler ×2 | Skills agently-mail`），同名重复调用标注次数，无记录时不占位。技能按模型读取 `SKILL.md` 的父目录名及 `/skill:` 命令统计，包含 `flash` 原生嵌套记录中的成功读取；子 agent 包含名称匹配的子代理工具、已启动的 `flash` 工具结果，以及本扩展不产生会话条目的 `titler`（按会话记录，`/reload` 后仍保留，历史会话中上一进程的记录不恢复）。
- 保留其他插件状态。执行 / 计划是本扩展的两态工作流，不模拟 Claude Code 的完整权限系统，也不虚构代理数。
- 支持主题配色和窄屏截断；其他扩展替换状态栏时不干扰对方。

#### 本轮平均输出速率

`tok/s` 在整轮结束后显示于输出用量与费用之间，不增加行数，不实时刷新：

```text
本轮平均输出速率 = 本轮成功模型响应的输出 token 总数 ÷ 这些响应的原生 durationMs 总秒数
```

- 不使用旁边的会话累计输出量；包含供应商计入输出的推理 token，以及请求内的首 token 等待等耗时，不代表纯文本吐字或解码速度。
- 工具执行、调用间空档及 Pi 的重试等待不计入；失败、取消、待完成 / 延迟响应及工具内嵌模型调用不参与。
- 任一成功响应缺少有效用量或耗时，或整轮无输出时隐藏。
- 新一轮、重载或切换会话时清空。

#### 本轮工具统计

- 采用 `✓ Read ×19 | ✓ Bash ×1` 样式，位于上下文资源行下方、状态 / 用量行上方，不显示 `Tools` 或总数前缀，按次数降序排列。
- 工具名使用弱化文字、次数和分隔线使用暗色。成功标记为绿色 `✓`；同名工具有失败记录时改为红色 `✗`，有未完成记录且无失败时使用黄色 `!`。
- 只统计本轮已保存的结果，包含失败及原生记录的嵌套调用；记录不完整时在工具行开头用 `≥` 标示，无调用时不占额外行。
- 新一轮开始时清零，结束后保留本轮结果；重载或切换会话时清空。

## 配置与状态

本扩展不再读写功能开关配置。旧的 `~/.pi/agent/extension-settings/omp-editor.json` 即使保留 `false` 也不会关闭功能；该文件不会被自动改写或删除，可按需自行删除。

执行 / 计划模式仍保存在会话分支的 `omp-interaction-mode` 自定义条目中，通过 `Shift+Tab` 或 `/omp-mode` 切换，与功能启用无关。

## 本地开发

项目采用 JavaScript ES Modules，使用 Node.js 内置测试运行器，无单独构建步骤。四个 peer dependencies 为 `@earendil-works/pi-ai`、`@earendil-works/pi-agent-core`、`@earendil-works/pi-coding-agent` 和 `@earendil-works/pi-tui`，运行时由 Pi 提供，本地开发时需安装。

在项目根目录执行：

```bash
npm install --ignore-scripts
```

隔离加载本地扩展，进行交互验证：

```bash
pi --no-extensions -e .
```

`--no-extensions` 仅在本次启动禁用其他自动发现、已配置及内置扩展，包括内置 MCP 扩展；显式指定的 `-e .` 仍会加载。

运行测试与打包预检：

```bash
npm test
npm pack --dry-run
```

## 兼容性与排查

- **升级 Pi 后界面异常**：本项目适配了 Pi 内部 UI 接口，升级后可能需要调整；目前仅验证 Pi 1.3.0。
- **输入框被覆盖或重复加载**：检查是否安装了其他输入框扩展，或仍保留旧版 `omp-editor.js` / `done.js`；将旧脚本及备份移出自动加载目录后执行 `/reload`。
- **工具卡片没有启用**：检测到 `pi-cc-extensions` 接管工具渲染时会自动让位；移除该渲染器并 `/reload` 后可使用内置工具 UI。
- **状态栏未显示**：其他扩展使用自定义状态栏时，本扩展不会覆盖对方。
- **会话没有自动标题**：已有名称不会覆盖；未命名时检查警告及 Pi 的 `deepseek/deepseek-flash` 模型配置和鉴权。标题子 agent 不使用主模型兜底，修复配置后可在下一轮有效交互结束时重试。
- **工具提示 Plan mode 被阻止**：用 `/omp-mode status` 检查模式；如需修改文件或运行命令，待本轮结束后切换 `/omp-mode execute` 并重新发出请求。
- **需要隔离定位问题**：在本项目根目录使用 `pi --no-extensions -e .` 启动，仅加载本地扩展进行对比。
